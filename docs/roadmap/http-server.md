# HTTP-сервер: ревизия, покрытие, безопасность

Статус: заготовка · Приоритет: P2 · Зависимости: —

## Зачем

Axum-сервер (внешние клиенты: ИИ-агенты, MCP) устарел: давно не
развивался, часть нового функционала не имеет конечных точек — например,
плагины. Плюс безопасность конечных точек отсутствует как класс: сейчас
голый доступ без аутентификации.

## Что делаем

- Ревизия «что там лежит»: покрытие Tauri-команд HTTP-эндпоинтами,
  расхождение с текущим состоянием доменов.
- Добавить недостающие конечные точки (плагины и пр.).
- Безопасность: аутентификация клиентов (токены), запрет голого доступа.

## Открытые вопросы

- Метод ревизии: аудиторский проход `client/command/` vs `server/endpoints/`
  с таблицей покрытия.
- Форма аутентификации: bearer-токены? Куда встраивать (middleware Axum)?
- Разграничение скоупов: HTTP-доступ внешних клиентов к функциональности
  плагинов — здесь; межплагинный Plugin Gateway — отдельная заметка
  ([Plugin Gateway](./plugin-gateway.md)).
- UI-механизмы доступа (токены, «вежливый стук») — пока на уровне идеи:
  [server-access-ui](../идеи/server-access-ui.md).
