# Настройки

Статус: заготовка · Приоритет: P2 · Зависимости: —

## Зачем

Две категории настроек:

- **Общие** — верхний уровень, действуют на приложение напрямую
  (например, тема по умолчанию); на курсы и плагины — как общий
  шаблон, применяемый к курсу по умолчанию.
- **Специализированные** — после создания курса к нему применяются
  настройки из общего пула, но для конкретного курса могут
  переопределяться; приоритет по умолчанию выше общих.

## Прогресс

- Пакет `@mai/settings`: пользовательские настройки документом на пункт
  `(domain, itemId)`; IPC `settings_get/update/delete`, валидация значений на
  бэкенде по реестру схем.
- Системные «Общие» (`system/general`, `theme` + `language`) описаны тем же
  `definePluginSettings`, что и настройки плагинов, и рендерятся общей формой
  `SettingsSchemaForm`; тема и язык применяются реактивно.
- Настройки плагинов — Zod-схема в `definePluginSettings`, UI генерируется по
  self-describing полям (`settingsFieldSpecs` → `SettingsFieldRenderer`), переводы
  полей — по конвенции ключей `<поле>.label|.hint|.options.<значение>` в namespace
  определения.
- Состояние пункта — общий стор по ключу `domain:itemId`, автосохранение с паузой,
  сброс через удаление документа.
- Открыто: панель настроек курса (домен `course`) и переопределение общих
  настроек курсом — домен уже поддержан бэкендом и стором.
