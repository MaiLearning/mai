# Конфигурация бэкенда через mai.toml

Статус: идея · Зависимости: [пакет @mai/config](../../src/packages/config/docs/README.md)

## Зачем

Бэкенд (и особенно его БД-часть) пока конфигурируется собственными
механизмами (`database::sqlite::settings`, учёт dev/prod). Единый `mai.toml`
задумывался как связующее звено для фронта и бэкенда — логично, чтобы
бэкенд тоже читал его и брал оттуда свои настройки.

## Что делаем

Выносим из внутренней конфигурации бэкенда параметры, которые зависят
от режима, и объявляем их вложенными секциями режима:

```toml
[mode.development]
debug = true
fake_data = true
hot_reload = true

[mode.development.server]
host = "localhost"
port = 8000

[mode.development.database]
path = "./data/development.db"
```

Каждый режим может расширяться по внутренним функциям (server, database, …).
Кроме того — независимые от режима модули:

```toml
[application]
window_width = 1280
window_height = 800
```

Ожидаемый эффект:
- один источник правды для всей конфигурации проекта;
- выбор `.dev`/`.release` директорий и портов без правки Rust-кода;
- настройки окна (dimensions) — объявлением, а не хардкодом.

## Открытые вопросы

- Где живёт выбор БД-файла: только путь, или целиком конфиг подключения?
- Насколько строго валидировать новые секции (zod дорастёт, или бэкенд получит свою serde-схему)?
- Синхронизация между изменением файла и «горячим» перезапуском подсистем.
