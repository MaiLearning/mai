# Известные проблемы MCP-слоя

Живой список того, что **не сделано**: ревизия реализации, проверка через
подключённый MCP и прогон вживую на данных. Закрытые пункты сюда не попадают —
их место в истории коммитов и в самом `MCP.md`.

Список живой: починил — вычеркни пункт и перенеси в описание того, почему чинить
не надо.

Легенда приоритетов:

- **Б** — блокер релиза;
- **1.0.1** — заметно для агента, но не ломает работу;
- **долг** — техдолг, в 1.0.0 не тянем.

---

## Б — блокер

### `mai_course_outline` отдаёт «узлов 0» на несуществующем курсе

`tools/course_outline.rs` не проверяет существование курса.
`StructureService::get_structure` (`src/services/structure/service.rs:37-45`)
валидирует только **формат** id (`StructureRules::validate_course_id`) и
возвращает пустой список для несуществующего курса.

```
courseId: 00000000-0000-0000-0000-000000000000
→ узлов 0 · ресурсов 0
```

Нарушает инвариант из `MCP.md` («несуществующий ресурс = `NotFound`, иначе
опечатка в id выглядела бы "успехом" с пустым содержимым») и обещание
`instructions.md` («не найдёшь — получишь `not found`»).

Почему это блокер, а не «долг»: опечатка в `courseId` — самый вероятный промах
агента, и сейчас он получает уверенно-неверный ответ вместо ошибки. Для
read-only сервера инспекции неверный ответ хуже, чем отсутствующая возможность:
агент не узнает, что ошибся, и пойдёт дальше строить выводы на пустом курсе.

Чинить на границе MCP-слоя, не в сервисе: `get_structure` вызывается ещё и
REST-эндпоинтом `/structures/by-course/{id}`, и смена его контракта утащит в
1.0.0 REST, который не релизится. Проверка — `CourseService::get` (одна выборка
по PK), текст ответа — русский actionable через `render::tool_error`.

`mai_search` не затронут: он берёт курсы из `CourseService::all`, там все
существуют.

## 1.0.1 — заметно для агента

### Формат содержимого `code` описан неверно, в трёх местах

Сказано «JSON с файлами» / «JSON: файлы и язык». Фактически поля `files` в
содержимом нет вообще:

```json
{"steps": [{"id", "title", "instructions", "starterCode", "expectedOutput"}],
 "code": {"<stepId>": "<исходник>"}, "results": {"<stepId>": …}, "language": "…"}
```

Агент будет искать `files` и не найдёт.

- `resources/md/glossary.md:36` — строка `code` в таблице `typeKey`;
- `instructions.md:62` — «код — как JSON с файлами»;
- `router.rs:78` — «code — JSON с файлами» в описании `mai_get_content`.

Заменять на реальную форму с именами полей.

### Глоссарий не упоминает `link`

`resources/md/glossary.md` перечисляет три `typeKey` (theory, task, code), а в
базе живут четыре: ресурсы с `typeKey = "link"` есть, они создаются через
UI/REST, а не кодом плагина — поэтому такие ресурсы не находятся грепом по коду.

Раздел «Связи» при этом описывает домен, но не говорит, что инструмента для
связей нет и что содержимое `link` наружу не выставлено: доступно только имя
узла. Агент, прочитавший глоссарий, будет искать связь и не найдёт.

Правка: строка `link` в таблице `typeKey` с пометкой о недоступности + оговорка
в разделе «Связи».

### Ошибки `Not found` — английские и не actionable

`mai_get_content: Not found: Resource '…' not found`,
`mai_get_course: Not found: Course '…' not found`. Это голый текст сервисного
слоя. `MCP.md:105` требует actionable-сообщений («что делать дальше»), а самый
частый агентский промах получает худшее из всех — на фоне соседних русских
сообщений с подсказкой.

Решение — один хелпер в `render.rs` рядом с `tool_error`:
`not_found(tool, что, id, next)`, подключить в `course_outline`, `get_course`,
`get_resource`, `get_content`. Одно место, один стиль, ноль повторов.

Сервисный слой остаётся английским: фронт этих сообщений не цитирует, так что
локализация не разъедется по приложению.

### Порт сервера не discoverable в release-сборке

`server/server.rs:25-26` объявляет адрес через `println!`, а
`src/main.rs:2` в release ставит `windows_subsystem = "windows"` — stdout
глотается. В собранном приложении на Windows порт не узнать: UI, настройки,
IPC-команды с портом нет.

Если MCP в 1.0.0 — фича релиза, то это не полировка, а вопрос «сможет ли
пользователь подключиться». Дёшево: `println!` → `log::info!` (попадёт в
лог-файл, который уже есть) плюс строка в настройках, если нужна
discoverability.

## долг

### `tool_error` идёт мимо капа и эхо-ит сырой ввод агента

`render.rs:90` — результат-ошибка не проходит через `text()`, поэтому
ограничения размера на нём нет. `tools/course_outline.rs:66` вставляет
агентский `rootId` прямо в эту строку — неограниченное эхо. Для остальных
инструментов размер ошибки не ограничен вовсе.

### Числовые аргументы без верхнего клампа

`depth` (`tools/course_outline.rs:40`), `max_nodes` (`:48`), `max_results`
(`tools/search.rs:90`), `max_scan` (`:91`) — `Option<usize>` с
`.unwrap_or(DEFAULT)` и без потолка сверху. Агент может передать `usize::MAX`
и отключить всю дисциплину размера. Самоограничение держится только на
добросовестности.

### Агентский `query` попадает в шапку отчёта без экранирования

`tools/search.rs:152` — сырая подстановка в строку `запрос «{query}»` над JSON
телом ниже. Портит формат отчёта и открывает вектор prompt-injection.

### Prompt-injection поверхность

Текст из БД и плагина попадает в контекст модели без экранирования:
`content/theory.rs:236` (`[вставка {url}]{caption}`), `:249` (`![{alt}]({src})`),
`:340` (`[{out}]({href})`). `href`/`src` с `)` формируют произвольную
разметку. Слой — доверенная граница к модели, но экранировать ссылки дёшево.

### `render/outline.rs` — две мелочи на границах

- `render/outline.rs:232` — `finish()` ставит `truncated` при нулевом остатке
  бюджета, даже если ничего не отрезано: ложное «усечено».
- `render/outline.rs:155` — ветка `Root::Chain` при обрыве по `MAX_CHAIN`
  (цикл в `parentId`) режет путь молча, без маркера.

### Кап считается в символах, не в байтах

`render.rs:26` — 40 000 символов кириллицы это ~160 КБ ответа, плюс два
прохода по телу при подсчёте. Для агента важнее символы, так что это скорее
замечание, чем дефект.

### Дыры в покрытии

Не покрыты тестами: `mai_list_plugins`, `mai_get_resource` в обоих `detail`,
успешный путь `mai_get_course`, негативные и огромные аргументы (`depth: -1`,
`maxNodes: usize::MAX`), соблюдение капа в `tool_error`.

### `instructions.md` не упоминает два инструмента

`mai_get_course` и `mai_list_plugins` есть в роутере и работают, но в
`instructions.md` не названы. Маршрут идёт `list_courses` → `outline` →
`get_resource` → `get_content`, поэтому `mai_get_course` из маршрута выпадает —
на практике инструмент без документации.

### `tools/search.rs` — 327 строк

Выше потолка проекта (200, `AGENTS.md` → правила размера). До правок был 307,
то есть это предсуществующий долг, который мои изменения увеличили на 20 строк.
Распил — по смысловой границе: выборка и обход в одном файле, разчёт попаданий
и рендер — в другом.

## Вне MCP

### `GET /resources` ведёт 400

`src/server/endpoints/resource/router.rs:10` — роут `list` ведёт на
`get::handler`, которому нужен `Path(id)`. Не MCP, а близнед его поверхности.
Отложено решением: REST в 1.0.0 не уезжает. Чинить при возвращении REST,
`ResourceService::list` уже есть (`src/services/resource/service.rs:176`) и
никем не задействован.

### Русский UI показывает английские сервисные ошибки

Побочное наблюдение локализации: сообщения сервисного слоя приходят в русский
интерфейс как есть. В 1.0.0 не трогаем, но при централизованной локализации
сервисов задача сразу станет общей для обоих контуров.

## Чем это проверялось

Ревизия чтением кода плюс прогон живого MCP на реальных данных — он же
подключён как инструменты агента. Живой прогон выявил то, что чтение кода
показать не смогло: существование ресурсов с `typeKey = "link"` (создаются
через UI/REST, поэтому грепом по коду не находятся) и поведение
`mai_course_outline` на несуществующем курсе.

Обрезку json >40 000 символов вживую проверить не удалось: harness, через
который подключён агент, режет вывод примерно на 25 КБ, то есть ниже капа Mai.
Закрыто тестом `big_theory_json_is_trimmed_and_stays_valid`.
