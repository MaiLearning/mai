# Глоссарий Mai

Подробный разбор терминов платформы. Короткая версия — в инструкциях сервера;
здесь то, что нужно при работе с конкретными сущностями.

## Курс

Верхний уровень платформы. Поля, которые важны агенту: `id`, `name`,
`description`, `tags`, `status` (`draft` / `in_progress` / `completed`).
Даты и цвета карточки агент не получает — в краткой карточке их нет.

## Ресурс

Единица материала внутри курса. `resourceId` идентифицирует ресурс, `courseId` —
курс-владелец, `typeKey` — вид материала.

Поля по уровням детализации:

- кратко (`detail: "brief"`, по умолчанию): `id`, `name`, `typeKey`, `updatedAt`;
- полностью (`detail: "full"`): плюс `metadata` (произвольный JSON плагина) и
  `files` (имена файлов ресурса). `metadata` — сырое и непрозрачное поле,
  не рассчитывай на известную структуру.

`createdAt` / `updatedAt` — миллисекунды эпохи. В оглавлении видно только
`upd:` у узла-ресурса.

## Тип ресурса

`typeKey` определяет, какой плагин владеет содержимым и в каком формате оно
лежит:

| `typeKey` | Плагин | Формат содержимого |
|-----------|--------|--------------------|
| `theory`  | theory  | документ редактора (TipTap/ProseMirror JSON) |
| `task`    | task    | JSON: список задач, ответы, прогресс |
| `code`    | code    | JSON: файлы и язык |

`typeKey` может быть пустым — тогда содержимого у ресурса нет, и
`mai_get_content` вернёт ошибку, а не пустоту.

## Структура курса

Дерево узлов. Узел — **позиция** ресурса в дереве, а не сам ресурс.

- **Директория** — узел-группировка: имя и вложенные узлы, своего содержимого
  нет. Директория, у которой один потомок, в оглавлении схлопывается.
- **Узел-ресурс** — привязывает `resourceId` к позиции и имени в дереве.

Один ресурс занимает ровно один узел. Имя узла берётся из имени ресурса (или
директории) и не обязано совпадать с тем, что вернёт `mai_get_resource`, если
ресурс переименовали в другом месте.

Плоский список узлов наружу не отдаётся: `mai_course_outline` отдаёт готовое
дерево текстом, одна строка на узел.

## Связи

Направленные рёбра между ресурсами и курсами: `resource` → `resource`,
`resource` → `course`, `resource` → внешний `uri`. У каждого ребра есть
`ownerPluginId` — плагин, создавший связь, — и вычисляемый `targetStatus`
(`ok` / `broken`), показывающий, жива ли цель.
