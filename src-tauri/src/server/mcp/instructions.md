# Mai — доступ к данным платформы для ИИ-агента

Read-only доступ к курсам, структуре и содержимому ресурсов Mai. Мутаций нет.

## Глоссарий

Термины платформы. Путать их — главный источник неверных правок.

- **Курс** — верхний уровень, контейнер всего остального. Идентификатор `courseId`.
- **Ресурс** — единица материала внутри курса: лекция (теория), набор задач, файл с
  кодом. У ресурса есть `resourceId` и `typeKey` — тип определяет, какой плагин
  владеет его содержимым.
- **Тип ресурса** (`typeKey`) — вид материала: `theory`, `task`, `code`. От типа
  зависит формат содержимого.
- **Структура курса** — дерево узлов: директории (группировки) и ресурсы.
  Узел — это **позиция ресурса в дереве**, а не сам ресурс: один ресурс занимает
  ровно один узел.
- **Директория** — узел-группировка без содержимого, только имя и вложенные узлы.
- **Связь** — направленное ребро между ресурсами/курсами (ссылка, бэклинк).

**Ресурс ≠ узел структуры.** `mai_get_resource` отдаёт сам материал,
`mai_course_outline` — его место в дереве. Одно без другого бесполезно.

## Идентификаторы

- Все id — UUID, приходят только из ответов инструментов. **Не выдумывай id**
  и не перебирай похожие: не найдёшь — получишь `not found`.
- `courseId` нужен почти всегда: он есть в `mai_list_courses` и в каждом
  ответе по ресурсу.
- Плоский список без дерева — не причина: `mai_course_outline` отдаёт готовое
  дерево.

## Маршрут работы

1. `mai_list_courses` — найти курс.
2. `mai_course_outline` — найти нужный узел, получить `resourceId`.
3. `mai_get_resource` — карточка ресурса (по умолчанию краткая).
4. `mai_get_content` — содержимое, если оно нужно целиком.
   **Или `mai_search` — если нужно найти место, а не прочитать всё.**

Порядок именно такой: не читай содержимое, пока не выбрал ресурс.

## Дисциплина размера

Содержимое ресурса может быть большим. Экономия идёт не сжатием, а тем, что
агент не выкачивает лишнее.

- **Не читай содержимое целиком, чтобы найти одно место.** Для этого есть
  `mai_search`: он отдаёт совпадения с идентификаторами, а не тело ресурса.
- **Списки — всегда кратко.** `mai_list_courses` и `mai_get_resource` по умолчанию
  отдают карточку без `metadata` и файлов. Полное — только `detail: "full"`, и
  только для того ресурса, с которым работаешь прямо сейчас.
- **Оглавление ограничено намеренно.** `mai_course_outline` по умолчанию
  показывает 2 уровня и до 200 узлов. Если вывод обрезан — это сигнал сузить
  выборку (`rootId`, `depth`, `typeKeys`), а не читать остальное подряд.
- **`detail: "full"` — осознанный выбор.** Не переключай его «на всякий случай».

## Форматы содержимого

Формат задаёт `typeKey` ресурса, а не инструмент: теория приходит как документ
редактора, задачи — как JSON со списком задач и прогрессом, код — как JSON с
файлами. Что означает каждый `typeKey` и какие у него поля — в
`mai://guide/glossary`.

## Чего здесь нет

- Создания, изменения и удаления — сервер только читает.
- Списка всех ресурсов курса одним вызовом: для этого оглавление с фильтром
  `typeKeys`, дальше точечные `mai_get_resource`.
