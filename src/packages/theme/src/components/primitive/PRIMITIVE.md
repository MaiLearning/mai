# primitive/

**Примитивы** — слой компонентов с собственным состоянием.

Примитив решает одну **интерактивную или визуальную задачу** и обладает
полноценным набором свойств:

- собственным **поведением** и **состоянием**;
- **accessibility** (роли, aria-атрибуты);
- **keyboard interaction** и management фокуса;
- определённой **структурой** и **API для композиции**.

## Пример

```tsx
<Button
  variant="primary"
  size="md"
>
  Save
</Button>
```

`Button` знает о действии (click, disabled, loading), о своём состоянии и
о том, как принимать фокус.

## Главное отличие от фонда

- **Фонд** = generic UI infrastructure: механизм, не знающий о
  пользовательских действиях.
- **Примитив** = semantic UI behavior: полноценное интерактивное и/или
  визуальное представление, которое уже решает задачу.

Примитив может быть самодостаточным представлением сам по себе — ему не
нужен контекст извне. Конкретнее: **примитив создаётся самостоятельно или на
механизмах фонда**, но не обязан на них. `Input` стоит один; `Button`
собран на `Spinner`, а `Alert` — на `Box` и `Stack`.

## Как это связано с остальными слоями

- **Фонд** — база системы: раскладка, типографика, обёртки.
- **Паттерны** — примитивы выступают строительными блоками: композиция
  элементов фонда и/или примитивов даёт устойчивую переиспользуемую
  структуру. Паттерн может быть источником контракта для
  примитивов-участников: контролы читают контракт из паттерна (например
  контракт `Control` живёт в `pattern/field`).
- **Пакеты** — примитивы входят в состав законченных продуктов:
  `@mai/fields` строится на `Input`, `@mai/dropdown-menu` — на `Button`.

Зависимости строятся вокруг базы, а не вертикальной цепочки —
ограничений на «примитив → паттерн» нет. Инварианты модели: граф импортов
ацикличен; фонд не импортирует из верхних слоёв; компоненты не зависят от
продуктовых пакетов.

## Что сюда относится

Интерактив:

- `Button`, `Checkbox`, `Switch`, `Link`, `Modal`, `Drawer`, `Input`,
  `SegmentedControl`.

Семантическая коммуникация:

- `Alert`.

Механизмы без собственного API:

- `overlay` — общий механизм модальных панелей (`useOverlayPanel` +
  `overlay.style`): портал, блокировка скролла, focus-trap, автофокус,
  восстановление фокуса, закрытие по Esc, таймер анимации. Потребляется
  `Modal` и `Drawer`, каждый задаёт собственную разметку подложки и панели.
  Разметку механизм не рисует — см. `overlay/OVERLAY.md`;
- `popover` — инфраструктура попапов (`usePopover` + `popover.style`).
  Потребляется пакетами `@mai/select`, `@mai/dropdown-menu`,
  `@mai/context-menu`.

`@mai/icons` — не примитив, а пакет, лежащий **ниже** примитивов: тема
зависит от него, и `Button`, `Alert`, `Drawer`, `Checkbox` берут иконки
оттуда. См. `packages/PACKAGES.md`.

У каждого примитива — собственная заметка `*NAME*.md` в его директории.
