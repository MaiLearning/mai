# components/

Директория UI-слоёв пакета `@mai/theme`. Это новая модель размещения
компонентов — замена плоской раскладки `src/ui/`, в которой абстракции
разных уровней лежали вперемешку.

> **Важно:** `src/ui/` — легаси. Миграция компонентов из него в
> `components/` идёт по группам одного назначения: сначала выбрана
> структура слоёв, затем каждый batch переносится с проверкой
> соответствия модели. Перенесено:
>
> - `foundation` — раскладка (`Stack`, `Flex`, `Box`), типографика и
>   представление (`Text`, `Heading`), индикация
>   (`Spinner`, `Progress`, `Badge`), поверхность (`Card`), прокрутка
>   (`ScrollArea`); иконки (`Icon` + глифы) вынесены в отдельный пакет
>   `@mai/icons`;
> - `primitive` — `Button`, `Link`, `Checkbox`, `Switch`,
>   `SegmentedControl`, `Alert`, `Modal`, `Drawer` (общий overlay-механизм
>   `primitive/overlay`), попап (`usePopover` + `popover.style`), `Input`
>   (новый примитив ввода);
> - `pattern` — `Field`, `CheckboxGroup`, `Breadcrumbs`, `NavList`,
>   `PageHeader`.
>
> Осталось в `src/ui/` (по решению): `Select`, `DropdownMenu`,
> `ContextMenu`, `List`, `HierarchicalList`, поля (`ui/fields/`) —
> ожидают слоя `component/`/отдельного пакета.
> Подробности текущего состояния — в `foundation/FOUNDATION.md`,
> `primitive/PRIMITIVE.md`, `pattern/PATTERN.md` и заметках `*.md`
> у компонентов.

## Модель: четыре уровня абстракции

Компоненты разделяются не по размеру, а по **уровню ответственности**.
Три из четырёх уровней живут здесь, четвёртый — вне пакета темы:

| Слой | Назначение | Где живёт |
|---|---|---|
| `foundation/` | Фундаментальные строительные блоки, универсальные механизмы организации и представления интерфейса. Не решают пользовательских задач. | здесь |
| `primitive/` | Самодостаточные UI-абстракции, решающие одну интерактивную или визуальную задачу: состояние, поведение, accessibility, keyboard/focus, API композиции. | здесь |
| `pattern/` | Устойчивая композиция элементов `foundation/` и/или примитивов — структура и инфраструктура со своим API, переиспользуемая под разные контролы. Ещё не конечный продукт. | здесь |
| `component/` | Законченные продукты системы (TextField, DateField, Sidebar, WYSIWYG…). Собираются из паттернов и примитивов. | **отдельный пакет** (например `@mai/components`) |

Каждый слой описан в собственном `.md` внутри своей директории:

- `foundation/FOUNDATION.md`
- `primitive/PRIMITIVE.md`
- `pattern/PATTERN.md`

## Стори-титулы

Стори перенесённых компонентов группируются по слою и называются по схеме

```
UI/<Слой>/<Элемент>
```

где `<Слой>` — один из уровней модели (`Foundation`, `Primitive`, `Pattern`),
а `<Элемент>` — конкретный компонент. Примеры:

```
UI/Foundation/Stack
UI/Foundation/Flex
UI/Foundation/Box
```

Элементы, ещё не перенесённые из `src/ui/`, до миграции сохраняют старые
титулы (`Theme/Components/*`) и переименовываются в `UI/<Слой>/<Элемент>`
в момент переноса в свой batch. Слой `component/`, живущий в отдельном
пакете, использует собственный группирующий префикс того пакета.

## Правила

- Все новые UI-компоненты темы создаются по этой модели внутри `components/`.
- У каждого компонента/примитива/фонда в его директории лежит заметка
  `*NAME*.md` (шаблон — `foundation/stack/STACK.md`): назначение, когда
  использовать / когда нет, API, примеры, список зависимостей.
- Слой `component/` намеренно **не** размещён в пакете темы: законченные
  компоненты могут требовать сторонних библиотек (ProseMirror, dnd-kit),
  что для темы недопустимо. Они выносятся в отдельный пакет (например
  `@mai/components` в `packages/` у корня темы). Их фундамент — всегда
  `@mai/theme` с готовыми примитивами и паттернами.
- Зависимости между слоями строятся вокруг базы, а не вертикальной цепочки:
  `foundation/` — база для всех слоёв; `primitive/` — самостоятельный или на
  фонде; `pattern/` — композиция элементов `foundation/` и/или примитивов со
  своим API; `component/` (внешние пакеты) — использует любой из слоёв.
- Паттерн может быть источником контракта для участников: контролы читают
  контракт из паттерна (например контракт `Control` живёт в `pattern/field`).
- Инварианты модели: граф импортов ацикличен; `foundation/` ничего не
  импортирует из `primitive/`, `pattern/`, `component/`; слои темы не зависят
  от внешних component-пакетов.
