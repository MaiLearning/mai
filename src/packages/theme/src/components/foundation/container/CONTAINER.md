# Container

- **Слой:** foundation
- **Файлы:** `container.tsx` / `container.style.ts` / `container.stories.tsx`

## Назначение

Центрированная область ограниченной ширины. Ровно три обязанности:

1. потолок ширины из шкалы `theme.layout.containerWidths`;
2. центрирование по горизонтали (`margin-inline: auto`);
3. горизонтальные поля, которые растут вместе с контейтором.

Это **специализация `Box`**: под капотом работает тот же нормализованный
блок, к которому добавлены перечисленные правила.

## Когда использовать

- Контент нужно удержать в читаемой ширине и не дать ему растянуться
  на весь экран (текст, листинг кода, каталог карточек).
- Нужна одна общая логика боковых полей, а не своя на каждой странице.
- Нужна именованная область для потомков: `Container` объявляет себя
  контейнером запросов под именем `container`, поэтому `@container`
  без имени внутри него работает от ширины контейнера.

## Когда НЕ использовать

- Нужен просто блок без потолка и центрирования — `Box`.
- Нужно разместить элементы рядом или столбцом — `Flex` / `Stack`.
- Нужна раскладка в несколько колонок — грид ещё не заведён; пока
  составляйте из `Flex` с переносом.

## API

| Пропс | Тип | Дефолт | Описание |
|---|---|---|---|
| `size` | `narrow \| read \| code \| wide` | `'wide'` | Ступень шкалы ширин: 400 / 760 / 860 / 1200px |
| `fluid` | `boolean` | `false` | Снять потолок: ширина 100% родителя, отступы сохраняются |
| `as` | `div \| main \| section \| article \| aside` | `'div'` | Семантический тег внешнего слоя |

Плюс все атрибуты `<div>` (кроме `children`, который уходит во внутренний
слой).

## Устройство: два слоя

```tsx
<ContainerRoot as={as}>     // max-width + margin-inline: auto
                            // container-type: inline-size; container-name: container
  <ContainerInner>          // поля, растущие по ширине контейнера
    {children}
  </ContainerInner>
</ContainerRoot>
```

Два слоя нужны из-за ограничения спецификации: **элемент с
`container-type` не стилизуется собственными контейрными запросами**.
Поля на внешнем слое сделали бы ширину контейнера зависимой от результата
его же запроса. Поэтому потолок и центрирование живут на внешнем слое,
а поля — на внутреннем.

**Инвариант:** горизонтальные поля ставит только внутренний слой.

## Адаптивные поля

Внутренний слой растит поля контейрным запросом от ширины `Container`.
Лестница задана **числами базовых шагов** (`theme.spacing.step`, по умолчанию
0.125rem) и живёт в самом компоненте — потребитель у неё один:

| Ширина контейнера | Шаги | Поле |
|---|---|---|
| < 35rem (560px) | 8 | 1rem |
| 35rem — 64rem | 12 | 1.5rem |
| ≥ 64rem (1024px) | 24 | 3rem |

Верхняя ступень — 24 шага, то есть 3rem; в каталоге имён `spacing.xs…xl`
такого значения нет (максимум `xl: 2rem`) — именно поэтому поля заданы
числами, а не именем. Значения проходят через `theme.utils.space()`, так
что смена базового шага или единицы затрагивает и их.

Пороги (35rem/64rem) — локальные константы компонента: ширины области, а не
отступы. Второй компонент с такой же лестницей — повод поднять её в
`theme.layout`.

## Примеры

```tsx
// Каркас страницы: потолок 1200px, поля 3rem на широкой области
<Container as="main">
  <PageHeader title="Курс" />
</Container>

// Текстовая колонка для чтения
<Container size="read">
  <Markdown source={theory} />
</Container>

// Листинг кода
<Container size="code">
  <CodeViewer source={source} />
</Container>

// Вся ширина, поля остаются
<Container size="wide" fluid>
  <Table />
</Container>
```

## Зависимости

Импортирует `box/box.style` (на нём строятся оба слоя) и собственный
`container.style`. Типы пропсов — из `base/theme`
(`layout.containerWidths`). Из `primitive/`, `pattern/` и `component/`
ничего не использует.
