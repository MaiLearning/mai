## Идеи

Какие компоненты можно (нужно) реализовать? Вот мои мысли по этому поводу:
1. `Tooltip` и как следствие его разновидности вроде `ActionTooltip`
2. `HelpMark` - фактически это иконка + разные варианты `Tooltip`, мне в проекте понадобится!
3. Еще как вариант - можно разновидности `Button` сделать вроде `ClipboardButton`

## Реализовано

- `Breadcrumbs` (`components/pattern/breadcrumbs`) - цепочка пути для шапки ресурсов,
  настроек и страниц разделов.
- `NavList` (`components/pattern/navList`) - навигационный список с группами.
- `PageHeader` (`components/pattern/pageHeader`) - шапка раздела.
- `Drawer` (`components/primitive/drawer`) - выезжающая панель; общий
  overlay-механизм (`components/primitive/overlay`) делит с `Modal`.
- `Container` (`components/foundation/container`) - центрированная область с
  потолком ширины (`layout.containerWidths`) и растущими полями; `Box`
  переосмыслен как база всех layout-компонентов.
- `Grid` (`components/foundation/grid`) - колоночная раскладка: шаблон треков
  (`columns` числом или строкой), упаковка по минимальной ширине трека (`min`),
  зазор и выравнивание элементов внутри треков.

## Известные долги

- **Шкала `spacing` — каталог, а не источник истины.** Замерено по
  потребителям: из 386 захардкоженных значений отступов старый каталог
  (4/8/16/24/32px) покрывал 131 (33%), а кратно 2px — 353 (91%). Поэтому
  источник истины теперь базовый шаг `spacing.step` (0.125rem), а число в
  пропсе — количество шагов. Остаток: те же 386 мест в `.style.ts`
  потребителей и 189 мест `theme.spacing.*` живут по-прежнему; перевод
  первых на токены — отдельная партия. Пока они сырые, смена
  `spacing.step` двигает только токенизированные места.
- **Лестница полей области локальна для `Container`** (`container.style.ts`:
  8/12/24 шага на порогах 35rem/64rem). Второй компонент с такими же
  полями — повод поднять её в `theme.layout` как `gutters`/`gutterWidths`.
- **Раскладка в потребителях ручная.** 655 раскладочных деклараций в 67
  `.style.ts` вне темы, из них `display: grid` — 23 места, `grid-template-*` —
  14. `Box`, `Container` и `Grid` готовы, но потребители на них ещё не
  переведены.
- **Потолок адаптивного числа колонок не вынесен в API `Grid`.** Из 23 мест
  с `display: grid` колоночная сетка — 10, и двум из них нужен именно потолок
  (`CourseLibrary.style.ts`: 1 → 2 @640 → 3 @960; `StatusPicker.style.ts`:
  1 → 3 @560). `min` задаёт плотность, а не потолок: при `minmax(280px, 1fr)`
  и зазоре 16px на 1200px влезает 4 колонки, а не 3. Лестницы остались в
  потребителях; ось брейкпоинтов в теме по-прежнему нет (0 вхождений), и её
  появление — отдельное решение, а не следствие этого компонента.
- **10 мест `display: grid; place-items: center` — это не грид**, а
  центрирование, и покрывается `Flex`; ещё 3 места `display: grid; gap: X` без
  колонок — это `Stack`. Ни то, ни другое в `Grid` не тащили намеренно.
- **3 предсуществующие ошибки `tsc` в `src/base/fonts/fontVariants.ts`** —
  импорты `.css` без объявления типа. Видны только при запуске `tsc` внутри
  пакета: в `src/packages/theme/tsconfig.json` не выключен
  `noUncheckedSideEffectImports`, а в TS 5.6+ он включён по умолчанию.
  Корневой `tsc --noEmit` (единственная проверка монорепозитория) проходит
  чисто. Лечится `declare module '*.css'` либо
  `noUncheckedSideEffectImports: false` в tsconfig пакета.
