# Миграции настроек

## Текущее решение

Механизм миграций настроек пока не реализуется. Это осознанное решение для
упрощения первой версии plugin settings.

Сейчас поддерживаются:

- добавление новых полей через Zod defaults;
- сохранение пользовательских значений в существующем self-describing payload;
- сброс настроек при несовместимом изменении.

Если обновление plugin settings потребует преобразования старых значений,
например переименования поля или изменения типа, настройки будут сброшены к
актуальным defaults. Автоматическое преобразование старых данных не
выполняется.

## Почему это решение принято

Поддержка версий и миграций требует отдельного контракта, проверки цепочки
версий, правил обработки несовместимых документов и тестирования старых
сценариев. До появления реальной необходимости этот слой не нужен.

## Когда вернуться к миграциям

Механизм понадобится, если plugin settings уже будут использованы в
установленных версиях приложения, а обновление должно сохранять старые
пользовательские значения. Тогда нужно будет определить версионирование,
миграционные операции, правила конфликтов и политику для невалидных данных.
