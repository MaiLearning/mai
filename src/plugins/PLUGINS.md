# Plugins — internal-плагины Mai

Internal-плагин — модуль `src/plugins/<name>/`, поставляемый вместе с билдом
приложения. В отличие от external-плагинов (пишутся через SDK, устанавливаются
пользователем в рантайме), internal не устанавливается и не удаляется —
он часть приложения.

## Как плагин подключается

- Плагин обслуживает один или несколько **typeKey** — типов ресурсов.
- `PluginViewer` (`src/features/plugin/`) по `typeKey` ресурса находит плагин
  и рендерит его корневой viewer-компонент (пропсы `PluginRenderProps`:
  `resourceId`, `courseId`, `data`, `onReady`).
- Регистрация viewer'а: запись `typeKey → компонент` в `INTERNAL_VIEWERS`
  (`src/features/plugin/registry.ts`) + реэкспорт viewer'а в
  `src/plugins/index.ts`.

## Корень плагина — внутренний API приложения

Каждый плагин в корне создаёт файлы, которые являются частью приложения —
своеобразный внутренний API, через который происходит расширение. Приложение
импортирует **только** корневые файлы плагина; его внутреннее устройство
снаружи не видно.

- **`viewer.tsx`** — обязателен: реализация или реэкспорт компонента-viewer'а,
  отображающего ресурс.
- **`index.ts`** — публичные реэкспорты плагина (viewer + публичные типы).
- **`core/`** — контракты: типы данных, реестры вариантов.

Остальные директории — по назначению содержимого: `components/`, `tasks/`,
`nodes/`, `lib/`, `dev/`. Группировка по типу артефакта (`styles/` и т.п.)
запрещена — стили оформляются соглашением `<name>.style.ts` рядом с файлом
(см. `.opencode/instructions/styles.md`).

## Существующие плагины

### theory
WYSIWYG-редактор теоретических материалов на TipTap. typeKey: `theory`.
Автосохранение контента, outline документа, строка состояния.

### task
Задачи семи типов: single choice, multiple choice, true/false, matching,
ordering, fill-in-blank, open answer. typeKey: `task`.
Backend-регистрация выполнена (internal-плагин `internal-task` в
`src-tauri/src/plugins/registry.rs` — при старте регистрируется в БД
вместе с типом ресурса `task`). Следующие фазы: wire-контракт данных в
сущности `@/entities/task-plugin`, подключение `TaskViewer` к
`INTERNAL_VIEWERS`, механизм проверки ответов.
